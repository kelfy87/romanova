# Romanova

Romanova — небольшой сайт для перевода обычных чисел в римские и обратно. Я сделал его как проект по информатике, потому что большинство похожих конвертеров просто показывают готовый ответ. Здесь можно увидеть разложение числа по разрядам, разобраться в правилах записи и сразу закрепить их в тренажёре.

Интерфейс и все объяснения сделаны на русском языке.

## Что умеет проект

- переводит десятичные числа в римские и обратно;
- объясняет результат по шагам;
- находит неканоничные записи вроде `IIII` или `IL` и подсказывает правильный вариант;
- поддерживает классический диапазон от 1 до 3 999;
- умеет работать с числами до 3 999 999 в расширенном режиме;
- содержит короткий справочник и таблицу записи по разрядам;
- предлагает тренировку из десяти заданий с тремя уровнями сложности;
- работает на компьютере и телефоне.

## Зачем здесь сервер

Первый вариант проекта был полностью статическим. Этого достаточно для простого калькулятора, но мне хотелось нормально разделить интерфейс и основную логику приложения.

Сейчас браузер отвечает за ввод, вывод и тренажёр, а основной перевод проходит через `POST /api/convert`. Сервер проверяет формат запроса, выполняет конвертацию и возвращает уже готовое разложение числа. Благодаря этому API можно отдельно использовать из другого интерфейса или приложения.

Проект не хранит введённые числа и не использует базу данных. Все запросы обрабатываются в памяти.

## Как проект появился

Я собрал его за два дня.

**Первый день.** Сначала выписал правила римской записи и сделал чистые функции перевода в обе стороны. После этого собрал основную страницу: поле ввода, переключение направления, пошаговый разбор и справочник. В конце дня прогнал весь классический диапазон от 1 до 3 999, чтобы проверить, что каждое число переводится туда и обратно без потерь.

**Второй день.** Разделил проект на клиент и сервер, вынес конвертацию в HTTP API и разбил код интерфейса на небольшие модули. Затем добавил тренажёр, расширенную запись больших чисел, адаптивную вёрстку и обработку ошибок. Отдельно проверил быстрый ввод: старый ответ сервера не должен перезаписывать более новое значение в поле.

## Стек

- HTML и CSS без UI-фреймворка;
- JavaScript с ES-модулями;
- Node.js 22 и встроенный модуль `node:http`;
- встроенный тест-раннер `node:test`;
- Prettier только для форматирования исходников;
- GitHub Actions для автоматического запуска тестов.

Я специально не добавлял Express, React и сборщик. Для проекта такого размера они усложнили бы запуск, а полезной работы почти не добавили бы. В результате у приложения нет обязательных зависимостей в production.

## Архитектура

```text
romanova/
├── frontend/
│   ├── index.html              страницы приложения
│   ├── public/                 статические файлы
│   ├── styles/                 оформление и адаптивная вёрстка
│   └── src/
│       ├── api.js              запросы к серверу
│       ├── converter.js        состояние и интерфейс конвертера
│       ├── practice.js         тренажёр
│       ├── reference.js        таблица разрядов
│       ├── router.js           навигация между разделами
│       └── dom.js              общие функции интерфейса
├── backend/src/
│   ├── app.js                  HTTP-маршруты и раздача файлов
│   ├── conversion.js           проверка запроса и сценарий перевода
│   └── server.js               запуск и остановка сервера
├── shared/roman.js             правила римской записи
└── tests/                      тесты алгоритма, API и интерфейса
```

Правила перевода лежат в одном модуле `shared/roman.js`. Сервер использует его для API, а браузер — для примеров, справочника и тренажёра. Так две части приложения не расходятся в том, какая запись считается правильной.

При каждом новом вводе клиент отменяет предыдущий запрос. Дополнительный номер версии запроса защищает интерфейс от редкого случая, когда отменённый ответ всё равно приходит позже актуального.

## Как запустить

Понадобится [Node.js](https://nodejs.org/) версии 22 или новее.

```bash
git clone https://github.com/kelfy87/romanova.git
cd romanova
npm start
```

После запуска откройте [http://127.0.0.1:3000](http://127.0.0.1:3000).

Устанавливать пакеты для обычного запуска не нужно. Открывать `index.html` напрямую тоже не нужно: фронтенд обращается к локальному серверу.

Для разработки можно включить автоматический перезапуск сервера:

```bash
npm run dev
```

## API

### Перевод числа

`POST /api/convert`

```json
{
  "value": "2026",
  "direction": "decimal",
  "extended": false
}
```

Ответ:

```json
{
  "decimal": 2026,
  "roman": "MMXXVI",
  "groups": [
    { "value": 2000, "roman": "MM" },
    { "value": 20, "roman": "XX" },
    { "value": 6, "roman": "VI" }
  ]
}
```

`direction` принимает `decimal` или `roman`. Поле `value` всегда передаётся строкой. Для чисел больше 3 999 нужно включить `extended`.

В расширенной текстовой записи скобки заменяют надчёркивание: `(IV)D` означает 4 500. Сервер принимает современную каноническую запись и возвращает понятную ошибку для других вариантов.

Проверить состояние приложения можно запросом `GET /api/health`.

## Тесты

```bash
npm test
```

Тесты проверяют:

- известные примеры и весь диапазон от 1 до 3 999;
- преобразование больших чисел;
- невалидные и неканоничные записи;
- ответы и ошибки HTTP API;
- доступ только к разрешённым статическим файлам;
- быстрый ввод, отмену запросов и потерю соединения.

Проверить форматирование:

```bash
npm ci
npm run format:check
```

## Ограничения

Romanova работает только с целыми положительными числами. Ноль, отрицательные значения и дроби не входят в классическую римскую систему и поэтому не поддерживаются.

Для больших чисел существует несколько исторических вариантов записи. В проекте используется понятная для обычного текста договорённость: символы в скобках считаются надчёркнутыми и умножаются на 1 000.

Тренажёр работает локально в браузере и не сохраняет результат после перезагрузки страницы.
